# AI-Assisted Workflow Log

This document details how AI tools were used during the development of this project, including code delegation, AI errors caught during development, and prompt excerpts.

---

## 1. AI Tooling Used
* **Gemini 3.5 Flash / Claude 3.5 Sonnet (via Cursor IDE):** Used for skeleton code generation, TypeScript type definitions, and MST algorithm logic.
* **ChatGPT (GPT-4o):** Used for drafting the CSS dark theme layout styling variables and SCADA color designs.

---

## 2. Delegation vs. Manual Writing

### What was delegated:
* **MST Algorithm Structure:** Prim's algorithm implementation for coordinate nodes was generated by AI.
* **Boilerplate Setup:** Express API routes, basic React mounting, and SQLite table declarations.
* **Component HTML/CSS:** Basic grid layouts, SVG text coordinates, and badge colors.

### What was hand-coded / strictly audited:
* **The Localization Boundary Rules:** The specific logic for traversing through unmetered gap poles while subtracting confidence, and the isolated sensor-malfunction noise filter, was written and verified manually.
* **Telemetry Verification Lock:** The logic enforcing downstream device checks before allowing a ticket to transition to `resolved` was audited line by line.

---

## 3. AI Failure Stories & Corrections

### Case 1: Ingestion DB Lock on Bursts
* **Symptom:** When generating a 5,000-message telemetry burst in tests, the AI-generated code wrote each telemetry log synchronously to SQLite using `await db.run()`. This immediately threw `SQLITE_BUSY: database is locked` errors due to write-concurrency limits.
* **Correction:** We manually refactored the pipeline to use an in-memory queue (`logQueue`) and a `flushLogs` batch scheduler that runs every 500ms using a single SQL transaction. This solved all concurrency and lock errors.

### Case 2: Infinite Loop in Topology Traversal
* **Symptom:** During MST topology construction for unverified DTs, the AI-generated code accidentally connected a child node back to a parent forming a loop in the graph. When the localization boundary engine ran its DFS/BFS search, it hit a stack overflow due to an infinite loop.
* **Correction:** Added a visited-set check (`inMST`) during Prim's algorithm edge creation and verified that the tree remains strictly a Directed Acyclic Graph (DAG) with a single root.
